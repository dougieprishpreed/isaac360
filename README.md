# The Binding of Isaac Rebirth Complete Edition for Xbox 360

`boi360` is a work-in-progress native port of **The Binding of Isaac Rebirth Complete Edition** from the **Windows Steam version** to the **Microsoft Xbox 360 XDK**.

The goal is to preserve the original game's content and behavior, including procedural generation, combat, items, progression, saves, local multiplayer, artwork, animation and audio. The gameplay runtime uses C++ compatible with Visual Studio 2010 and the Xbox 360 XDK. Windows host builds test the same runtime used by the Xbox adapter.

## Project status

The port is incomplete, and no playable Xbox 360 release is available. The target is the complete game: Normal, Hard and Greed modes, every character and unlock, original progression, and the full item/enemy/boss/room/audio presentation.

Resource readers, level generation, room components and the normal player lifecycle have been implemented and checked on Windows. A normal New Run now generates its first floor, registers the player, constructs and enters the selected starting room, completes placement and post-generation initialization, and executes repeated whole simulation ticks in that room. Each tick completes the `414dc0` actor/player update, `6712a0` collision, the disabled `8d8470` particle gate, the `8798f0` room-effect cache update, enemy updates and the primary projectile lifecycle. The reached ordinary `72c430` no-item path performs its actual `0x1280`/`0x1284` head-timer and `0x1e88` call-counter work. Primary fire consumes the evaluated shot vector and the real `fireDelay`/`shotSpeed`/`damage`/`range` stats; host evidence observes spawned tears, wall collision and range expiry. A generated Gaper encounter is killed by those tears, clears the room and opens a normal door. The player then crosses the cleared door into the exact linked room, where rocks and the next enemy set are constructed and the player is placed at the reciprocal door. The Windows host also observes the complete initialized player moving to the real room boundary, stopping stably and reversing.

Primary firing, bidirectional enemy/player damage, death and normal-door transitions now work on Windows. A stage-owned generated Gaper room constructs its actual spawn plan, updates the enemy, and the projectile system damages and kills it, sets room clear and opens a normal door. A cleared door accepts the player into the exact linked resident, including rocks and the next enemy set, places the player at the reciprocal door and continues whole ticks. Enemy contact damages the player on a 30-tick invulnerability cadence; a generated Gaper encounter kills the starting player after six hits, a 60-tick dying state reaches game over and restart rebuilds a ready player at full health. Treasure doors remain closed without a key, consume one key on contact and open; boss-room entry doors open on room clear, and the prepared Dingle boss (300 HP, slide/spit behavior) can be fought and killed to set the floor boss-defeated flag. Enemy walk cycles are composed from the original ANM2 tracks; Pooters and Dingle fire hostile tears that collide with the room and the player. Boss death opens a trapdoor and the adapter descends into a generated Cellar floor that keeps the surviving player, with stage-2 doors, enemies and pickups continuing to work; 24 sampled generated boss rooms all construct. All twelve floors now generate and descend, all 36 character slots start and tick, treasure/trinket/card/pill pedestals select and record ownership, starting collectibles and active slots are granted, bombs place/explode and destroy grids, Hard mode reaches ready, and a maintained set of item/pill/card/active effects applies stats, hearts and resources. The port now has a shared 44.1 kHz stereo mixer over all 1,150 unique original WAV effects (1,156 archive entries) plus the 14 reached music streams prepared from the original OGG sources. Gameplay events submit tears, impacts, deaths, pickups, doors, bomb explosions and player hurt; music starts from the original character jingle and switches to the Basement/Cellar/Burning Basement tracks. Windows uses `waveOut` and the Xbox adapter uses XAudio2; a missing device falls back to software mixing. The port is still not a fully playable release: remaining boss families and terminal-floor fidelity, remaining boss/enemy attack and death-FX variants, the remaining health-owner trigger effects, full progression/unlocks and character costumes, complete sound-ID/event mapping and music layer sequencing, and complete presentation remain unfinished. Passing host checks does not establish Xbox 360 playability.

The shared sources compile into an Xbox 360 XEX with the installed XDK. The current XEX has been booted hidden and muted under Xenia and initializes the target XAudio2 device (`PORT audio initialized device=1`); this is device initialization, not audible playback validation. Earlier target runs reached `PNR_READY`, consumed XInput frames, executed whole gameplay ticks and rendered rooms, Isaac, enemies, doors, tears and HUD hearts. Visible target playability and physical-console validation remain unproven, and full progression, remaining content fidelity and complete presentation are still open.

## Development requirements

- Windows with Visual Studio 2010 C++ build tools.
- Microsoft Xbox 360 XDK for target development.
- Python 3 and PowerShell for data preparation and verification. Audio preparation also needs `ffmpeg` on `PATH` (or `C:\ffmpeg\ffmpeg.exe`) to decode the original OGG music streams.
- A local copy of the Windows Steam game data, plus the prepared resource and reference inputs used by the development tools.

Original game data belongs in `boi360\game`, the repository root's `game/` directory, and remains read-only. Game files, prepared resources, development references and compiled binaries are excluded from the repository. A fresh clone therefore needs these local inputs before builds or verification can run.

## Windows gameplay target

`build/windows/boi360.exe` runs the same shared runtime directly on Windows with in-process keyboard/scripted input, no emulator focus and fast fixed-step execution. Build it with `tools/build_windows_target.ps1`. See `docs/WINDOWS_TARGET.md`. It renders the actual room, player, enemy, pickup and HUD art from the original assets, initializes a real `waveOut` device when one is available and can save verified screenshots. The prepared audio pack lives in `runtime/port/audio`; target deployments must include `runtime/port` (audio included) alongside the XEX. Run from the repository root so the relative audio and atlas paths resolve.

## Windows host verification

With the toolchain and local inputs configured, run from the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test_runs.ps1 -Seeds 128
```

This builds the maintained Windows executable and runs deterministic simulation checks without rendering or frame delays. Verification runs serially on one logical CPU and writes build products and reports under `build/` and `logs/`. It does not build an XEX or launch Xenia.
